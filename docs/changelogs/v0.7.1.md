# v0.7.1 Changelog

## Overview

Version 0.7.1 consolidates error handling for augmentation functions, introduces explicit state
management for stateful functions, and applies a thread-safety fix to the internal event bus.

---

## New: `AugmentationFunctionResultList`

A new `AugmentationFunctionResultList` class has been added to `it.wldt.augmentation.result`.
It extends `ArrayList<AugmentationFunctionResult<?>>` and acts as the unified return type for
augmentation function executions, carrying either a list of results **or** an
`AugmentationFunctionError` — not both.

**Key behaviors:**
- Once an error is set via `setAugmentationFunctionError()`, all mutating operations (`add`, `set`,
  `remove`, `clear`) throw `IllegalStateException`. Read operations remain available.
- `hasError()` indicates whether the list is in error state.
- `getAugmentationFunctionError()` retrieves the embedded error, or `null` if none.

**Constructors:**

```java
// Empty list — add results with the standard List API
new AugmentationFunctionResultList()

// Single-result convenience constructor
new AugmentationFunctionResultList(AugmentationFunctionResult<?> result)

// Error-state constructor — list is immediately immutable
new AugmentationFunctionResultList(AugmentationFunctionError error)
```

---

## Breaking: `StatelessAugmentationListener` Removed

The `StatelessAugmentationListener` interface (`it.wldt.augmentation.listener`) has been removed.
`AugmentationFunctionHandler` no longer implements it.

Stateless functions previously reported errors by calling `notifyError()`. That method is no
longer available in `StatelessAugmentationFunction`. Errors must now be returned directly from
`run()` by constructing a `new AugmentationFunctionResultList(error)`.

**Migration:**

```java
// Before (0.7.0)
protected List<AugmentationFunctionResult<?>> run(AugmentationFunctionRequest request)
        throws AugmentationFunctionException {
    try {
        // ...
    } catch (Exception e) {
        notifyError(new AugmentationFunctionError(AugmentationFunctionErrorType.ERROR, e.getMessage()));
    }
    return Collections.emptyList();
}

// After (0.7.1)
protected AugmentationFunctionResultList run(AugmentationFunctionRequest request)
        throws AugmentationFunctionException {
    try {
        // ...
        return new AugmentationFunctionResultList(result);
    } catch (Exception e) {
        return new AugmentationFunctionResultList(
            new AugmentationFunctionError(AugmentationFunctionErrorType.ERROR, e.getMessage())
        );
    }
}
```

---

## Breaking: API Signature Changes

All methods that previously accepted or returned `List<AugmentationFunctionResult<?>>` now use
`AugmentationFunctionResultList`. This affects:

| Component | Method / Callback | Change |
|-----------|------------------|--------|
| `StatelessAugmentationFunction` | `run()` return type | `List<...>` → `AugmentationFunctionResultList` |
| `AugmentationFunctionHandler` | `handleAugmentationFunctionExecution()` return type | `List<...>` → `AugmentationFunctionResultList` |
| `StatefulAugmentationListener` | `onStatefulAugmentationFunctionResult()` parameter | `List<...>` → `AugmentationFunctionResultList` |
| `DigitalTwinModel` | `onAugmentationFunctionResultEvent()` parameter | `List<...>` → `AugmentationFunctionResultList` |
| `AugmentationFunctionResultWldtEvent` | payload type | `List<...>` → `AugmentationFunctionResultList` |
| `StatefulAugmentationFunction` | `notifyResult()` parameter | `List<...>` → `AugmentationFunctionResultList` |

The `onStatefulAugmentationFunctionError()` method has also been removed from
`StatefulAugmentationListener` — errors from stateful functions are now embedded in the
`AugmentationFunctionResultList` passed to `onStatefulAugmentationFunctionResult()`. Stateful
functions continue to have `notifyError()` available for asynchronous error reporting via the
handler.

---

## New: Stateful Function State Management

`StatefulAugmentationFunction` now tracks whether it is currently running via an internal
`isRunning` flag. The flag is set automatically by the framework when `handleStart()` /
`handleStop()` are called.

**New public method:**

```java
public final boolean isRunning()
```

Returns `true` if the function has been started and has not yet been stopped.

**Guard checks in `DigitalTwinModel`:**

`startAugmentationFunction()` is now a no-op if the target function is already running, and
`stopAugmentationFunction()` is a no-op if the target function is already stopped. Both methods
log an informational message and return early without publishing an event.

---

## New: `DigitalTwinModel.isStatefulAugmentationFunctionRunning()`

Two new protected methods have been added to `DigitalTwinModel` to allow the shadowing function
to query the running state of a stateful augmentation function:

```java
// Search across all registered handlers
protected boolean isStatefulAugmentationFunctionRunning(String augmentationFunctionId)
    throws AugmentationFunctionException

// Target a specific handler
protected boolean isStatefulAugmentationFunctionRunning(String augmentationFunctionHandlerId,
                                                        String augmentationFunctionId)
    throws AugmentationFunctionException
```

Both methods throw `AugmentationFunctionException` if the function is not found or is not of
type `STATEFUL`.

---

## Fix: `WldtEventBus` Thread Safety

The internal event publishing loop in `WldtEventBus` now iterates over a **copy** of the
subscription event type set rather than the live key set. This prevents a
`ConcurrentModificationException` that could occur when a `QueryExecutor` callback modified
the subscription map while publishing was in progress.

This is an internal fix with no API surface change.
