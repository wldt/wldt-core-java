# v0.9.0 Changelog

Version 0.9.0 introduces two main features. First, a **new declarative Query System**: the request-type based `QueryRequest` is replaced by an immutable `Query` object (resource, filter, sorting, paging, aggregation, timeout) that is translated by the storage into its own native language, so only the needed records are returned. Second, **State Filters for Augmentation Functions**: a function can now choose *when* it is notified of a state update (trigger filter) and *which part* of the Digital Twin State it receives (content filter).

Key updates:

- **`Query` replaces `QueryRequest`** — built with `Query.on(resourceType)`, with filters, sorting, `limit`/`offset`, aggregations, total count and timeout
- **`WldtStorage` is query-driven** — the ~60 per-resource getters (`get…Count`, `get…InTimeRange`, `get…InRange`, `getLast…`) are replaced by a single `execute(Query)` method
- **`QueryResult` always returns records** — it is typed (`QueryResult<T extends StorageRecord>`) and built with `success(...)` / `failure(...)`
- **Filters and aggregations** — new `filter` and `aggregation` sub-packages, plus an in-memory evaluator used by `DefaultWldtStorage`
- **Query timeout** — configurable on the `Query` and on the `QueryExecutor`; expired queries are skipped by the `StorageManager`
- **Augmentation State Filters** — trigger filter (`StateChangeFilter`) and content filters (property, action, event, relationship names) in `AugmentationFunctionContextRequest`, both disabled by default
- **`observeState` / `observeEventNotifications` are now honoured** on the stateful push path
- **Optional query refresh on every state update** for stateful functions (`refreshQueryOnStateUpdate`)
- **Removal of the constructors deprecated in 0.8.1** (type-only constructors of State and Physical Asset properties and events)
- **Event bus robustness** — a failing subscriber no longer stops the delivery of the following events to the same subscriber

## Breaking changes

| Area | Change |
|------|--------|
| Storage | `QueryRequest` and `QueryRequestType` are **removed**. Use `Query` |
| Storage | `WldtStorage`: all the abstract getters by resource are **removed** and replaced by `abstract QueryResult<?> execute(Query query)`. Custom storages must implement `execute` (see below) |
| Storage | `QueryManager` / `DefaultQueryManager`: `handleQuery(Query, Map<String, WldtStorage>)` and `getTargetStorage(Query, Map)`; the per-resource `handle…Query` methods are **removed** |
| Storage | `QueryExecutor`: `syncQueryExecute(Query)` and `asyncQueryExecute(Query, IQueryResultListener)` |
| Storage | `QueryResult<T>` is now `QueryResult<T extends StorageRecord>`; the public constructors are replaced by the factories `success(query, items[, total])` and `failure(query, errorMessage)`; `getOriginalRequest()` is now `getOriginalQuery()` |
| Augmentation | `StatefulAugmentationFunction.onQueryResultRefresh(QueryRequest, QueryResult)` is now `onQueryResultRefresh(Query, QueryResult)`; same for `StatefulAugmentationListener` and `AugmentationFunctionHandler` |
| Event Bus | The query request event now carries a `Query` as body (`WldtEvent<Query>`) |

### Equivalence with the previous request types

| Previous request type | Equivalent query |
|---|---|
| `TIME_RANGE` | `where(and(gte(TIMESTAMP, start), lte(TIMESTAMP, end)))` |
| `SAMPLE_RANGE` (indices `a` to `b`) | `offset(a).limit(b - a + 1)` |
| `LAST_VALUE` | `orderBy(TIMESTAMP, DESC).limit(1)` |
| `COUNT` | `aggregate(count().as("count"))` |

### Before / after

```java
// 0.8.1
QueryRequest request = new QueryRequest();
request.setResourceType(QueryResourceType.DIGITAL_TWIN_STATE);
request.setRequestType(QueryRequestType.TIME_RANGE);
request.setStartTimestampMs(start);
request.setEndTimestampMs(end);
QueryResult<?> result = queryExecutor.syncQueryExecute(request);

// 0.9.0
Query query = Query.on(QueryResourceType.DIGITAL_TWIN_STATE)
        .where(and(gte(QueryFieldNames.TIMESTAMP, start), lte(QueryFieldNames.TIMESTAMP, end)))
        .build();
QueryResult<?> result = queryExecutor.syncQueryExecute(query);
List<DigitalTwinStateRecord> states = result.as(DigitalTwinStateRecord.class).getItems();
```

## New: Query System

### `Query`

Immutable description of a query created with the builder `Query.on(resourceType)`: filter, sorting (`SortCriterion`), `limit` / `offset`, aggregation, `withTotal` and `timeout`. `refresh()` returns a copy with a new `requestId`, useful to re-run the same query periodically.

### Filters and aggregations

| Package | Classes |
|---------|---------|
| `it.wldt.storage.query.filter` | `Filter`, `ComparisonFilter`, `AndFilter`, `OrFilter`, `NotFilter`, `FilterOperator`, `FilterVisitor`, `FilterFactory` (`eq`, `gte`, `and`, ...) |
| `it.wldt.storage.query.aggregation` | `Aggregation`, `AggregationGroupBy`, `AggregationMetric`, `AggregationFunction`, `AggregationPart`, `AggregationFactory` (`groupBy`, `count`, `avg`, ...) |

`QueryFieldNames` lists the fields usable in filters, sorting and aggregations. The result of an aggregation is an `AggregationRecord` (package `it.wldt.storage.model`), holding the group-by values and the computed metrics with typed getters (`getString`, `getLong`, `getDouble`).

`FilterVisitor` allows a custom storage to translate the filter tree into the native query language of its backend (SQL, MongoDB, ...).

### Results

`QueryResult<T extends StorageRecord>` always contains a list of records (`getItems()`), the optional total number of matches, the status and the error message. Helpers: `as(Class)`, `first()`, `last()`.

### Timeouts

- `QueryExecutor.DEFAULT_QUERY_TIMEOUT_MS` is 5000 ms; a new constructor `QueryExecutor(digitalTwinId, queryExecutorId, defaultTimeoutMs)` customizes it
- A query overrides it with `Query.Builder.timeout(long)`
- Timeouts and errors are reported as failed `QueryResult`
- The `StorageManager` **skips** queries whose timeout already expired (nobody is waiting for the result), so a backlog of abandoned queries does not delay writes and other queries
- If no `QueryManager` is set, the `StorageManager` now answers with a failed `QueryResult` instead of leaving the caller waiting

### Custom storages

A custom `WldtStorage` implements `execute(Query)` and translates the query to its backend. `DefaultWldtStorage` delegates to the new `InMemoryQueryEvaluator` (package `it.wldt.storage.query.inmemory`), which can also be reused by storages that have no native query engine. See `docs/storage_query_system.md`.

## New: Augmentation Function State Filters

Until 0.8.1 every `dt.state.update` was pushed, with the complete state, to every running stateful function. Two optional filters are now available in `AugmentationFunctionContextRequest`. They are **disabled by default**: with no filter the behaviour is unchanged (every update, full state).

### 1. Trigger filter (stateful functions only)

`StateChangeFilter` rules decide *when* a state update is pushed. A rule has optional criteria on **operation**, **resource type** and **resource name** (empty criterion = wildcard, non-empty criteria are AND-ed). The update is pushed if **any** change of the update matches **any** rule; if the update carries no change list, it is not pushed.

```java
StateChangeFilter.onPropertyValueUpdate("temperature", "humidity");
StateChangeFilter.onResources("near");
StateChangeFilter.builder()
        .operations(DigitalTwinStateChange.Operation.OPERATION_REMOVE)
        .resourceTypes(DigitalTwinStateChange.ResourceType.RELATIONSHIP_INSTANCE)
        .build();
```

### 2. Content filter (stateful and stateless functions)

`propertyNameFilter`, `actionNameFilter` (new), `eventNameFilter`, `relationshipNameFilter` decide *what* the function receives: a partial `DigitalTwinState` copy with only the selected resources, with the same `onStateUpdate(DigitalTwinState)` signature. Each category is independent: `null` keeps everything, an empty list removes it. The same filters apply to the state in the context of start / stop / execute (stateless included). `eventNameFilter` also drops the event notifications whose name is not listed.

### Configuration

```java
AugmentationFunctionContextRequest request = new AugmentationFunctionContextRequest()
        .withStateChangeFilters(StateChangeFilter.onPropertyValueUpdate("temperature", "humidity"))
        .withPropertyNameFilter("temperature", "humidity")
        .withActionNameFilter();      // no action delivered
```

Fluent methods: `withStateChangeFilters`, `withPropertyNameFilter`, `withActionNameFilter`, `withEventNameFilter`, `withRelationshipNameFilter`; helpers `hasTriggerFilter()` and `hasContentFilter()`. New classes: `StateChangeFilter` and `DigitalTwinStateFilterUtils` (package `it.wldt.augmentation.context`).

### Behaviour changes to be aware of

- `observeState = false` now stops state updates being pushed to a stateful function (it used to affect only the start / stop / execute context); `observeEventNotifications = false` now stops event notifications being pushed (it was ignored)
- The constructor `AugmentationFunctionContextRequest(boolean, boolean, Query)` now honours its two flags (it ignored them and always used `true`)
- `eventNameFilter` and the other name filters were declared but never read by the framework: setting them now has an effect
- The partial state has a new `evaluationInstant`
- The trigger filter does not apply to event notifications (use `eventNameFilter`) nor to stateless functions, which are request-driven

### Query refresh on state update (opt-in)

`AugmentationFunctionContextRequest.setRefreshQueryOnStateUpdate(true)` makes the handler execute the function's query and deliver the result (`onQueryResultRefresh`) before every state update notified to it. Disabled by default: the query runs synchronously on the handler thread. See `docs/augmentation_function.md`.

## Removed (deprecated in 0.8.1)

The constructors that set only the semantic `type`, deprecated in 0.8.1, are **removed**:

| Class | Removed constructor | Replacement |
|-------|---------------------|-------------|
| `DigitalTwinStateProperty<T>` | `(key, value, type)` | `(key, value, type, contentType)` |
| `DigitalTwinStateEvent` | `(key, type)` | `(key, type, contentType)` |
| `PhysicalAssetProperty<T>` | `(key, type, initialValue)` | `(key, type, contentType, initialValue)` |
| `PhysicalAssetEvent` | `(key, type)` | `(key, type, contentType)` |

Code using them no longer compiles. When creating State resources from a Physical Asset Description, copy `getType()` **and** `getContentType()` (see `docs/changelogs/v0.8.1.md`). Pass `null` as `contentType` only if the format is really unknown.

## Migration from 0.8.1

1. Replace the removed constructors listed above with the ones that also set the `contentType`.
2. Replace every `QueryRequest` / `QueryRequestType` with a `Query` (see the equivalence table above).
3. Update the signature of `onQueryResultRefresh` in stateful augmentation functions: `Query` instead of `QueryRequest`.
4. Read results through `QueryResult.getItems()` / `as(Class)`; use `QueryResult.success(...)` / `failure(...)` instead of the removed constructors, and `getOriginalQuery()` instead of `getOriginalRequest()`.
5. Custom `WldtStorage` implementations: remove the per-resource getters and implement `execute(Query)`.
6. Custom `QueryManager` implementations: adopt the new `handleQuery` / `getTargetStorage` signatures.
7. If a function relied on `observeState = false` / `observeEventNotifications = false` having no effect on the push path, review it: those flags are now honoured.
